🪶 Hermes Connection

Configure the NousResearch hermes-agent API server. When enabled, saying "hermes <your request>" routes the full message exclusively to this agent.

Turn on to enable the "hermes" voice prefix. Requires a working endpoint + API key below.
Where your hermes-agent server is reachable. Defaults to port 8642. Bare hostnames assume https://; host:port uses http://.
✅ Easiest: glasses + Mac on the same Wi-Fi

No Cloudflare account, no domain, no config files. Just paste your Mac's LAN IP into the field above.

  1. On the Mac, find your local IP:
    ipconfig getifaddr en0
    (Or: System Settings → Network → Wi-Fi → Details — look for "IP address".)
  2. Paste http://<that-ip>:8642 into the Endpoint URL field above. Example: http://192.168.1.170:8642
  3. Make sure Hermes is running on the Mac (hermes start or your usual command).

⚠ Won't work over cellular — only when the glasses are on the same Wi-Fi as your Mac. If you need remote access, expand the Cloudflare option below.

🌐 Need cell-network access? Use a Cloudflare Tunnel

A Cloudflare Tunnel gives your Hermes server a public https:// URL so the glasses can reach it over cellular. The quick mode below requires no account.

Recommended — Quick tunnel (no account, ~30 seconds)
  1. Install once: brew install cloudflared
  2. Run pointed at the Hermes port (default 8642):
    cloudflared tunnel --url http://localhost:8642
  3. The terminal prints a URL like https://random-words-1234.trycloudflare.com. Copy that and paste it into the Endpoint URL field above.

The URL changes every time you restart cloudflared, so re-paste after a restart. Tunnel runs only while that terminal is open.

⚙ Advanced: permanent URL on your own domain (named tunnel)

If you have a domain on Cloudflare and want a stable URL that survives restarts:

  1. One-time: cloudflared login
  2. Create a tunnel:
    cloudflared tunnel create hermes
  3. Route a hostname (replace hermes.example.com with one on a domain you own through Cloudflare):
    cloudflared tunnel route dns hermes hermes.example.com
  4. Edit ~/.cloudflared/config.yml to map the hostname to your Hermes port: 
    tunnel: <your-tunnel-id>
credentials-file: ~/.cloudflared/<id>.json

ingress:
  - hostname: hermes.example.com
    service: http://127.0.0.1:8642
  - service: http_status:404
  5. Start the tunnel:
    cloudflared tunnel run hermes
  6. Paste https://hermes.example.com into the Endpoint URL field above. The named-tunnel command does NOT print a URL — the URL is the hostname you mapped in step 3. Check anytime with cat ~/.cloudflared/config.yml.

One config.yml can list multiple hostname → service pairs so one tunnel serves Hermes, TapClaw, and the relay.

Set on the server side via hermes config set API_SERVER_KEY ... in ~/.hermes/.env (generate one with openssl rand -hex 32).
Forwarded as X-Hermes-Session-Id. main is the default; use distinct IDs (e.g. glasses) to isolate conversations.
Streaming budget — the longest Hermes may go between streamed chunks while it reasons or runs tools before the glasses give up. 0 = 30s. The effective wait is floored at 5 min, so raise this above 300 only for very long agent runs (max 600 = 10 min). If Hermes "sticks in limbo", a higher value here keeps the glasses from dropping the stream and killing the task mid-run.

☁️ Remote Access

Access TapClaw from anywhere using a Cloudflare Tunnel. This creates a secure public URL for your local gateway.

Setup instructions (named tunnel — recommended)
A named tunnel gives you a permanent, stable URL. Requires a domain on Cloudflare (from ~$2/year).

Step 1 — Install cloudflared:
brew install cloudflared

Step 2 — Log in to your Cloudflare account:
cloudflared tunnel login
A browser window opens. Authorize and select your domain.

Step 3 — Create the tunnel:
cloudflared tunnel create tapclaw
Note the tunnel ID from the output.

Step 4 — Route DNS:
cloudflared tunnel route dns tapclaw tapclaw.yourdomain.com

Step 5 — Create config file:
Create ~/.cloudflared/config.yml with:
tunnel: YOUR_TUNNEL_ID
credentials-file: /Users/YOU/.cloudflared/YOUR_TUNNEL_ID.json

ingress:
  - hostname: tapclaw.yourdomain.com
    service: http://localhost:18789
  - hostname: relay.yourdomain.com
    service: http://localhost:18790
  - service: http_status:404
Step 6 — Allow the origin in OpenClaw:
openclaw config set gateway.controlUi.allowedOrigins "https://tapclaw.yourdomain.com"
Then restart the OpenClaw gateway.

Step 7 — Start the tunnel:
cloudflared tunnel run tapclaw

Auto-start on login: brew services start cloudflared

Alternative: Tailscale (mesh VPN, free, no domain needed)
Troubleshooting
"origin not allowed" — Add your tunnel domain to ~/.openclaw/openclaw.json under gateway.controlUi.allowedOrigins and restart the gateway.

"503 Service Unavailable" — The tunnel is running but has no ingress rules. Check ~/.cloudflared/config.yml.

"Error 1033" in browser — The tunnel isn't running. Start it with cloudflared tunnel run tapclaw.

Vision relay not working remotely — Make sure your Cloudflare config includes the relay. subdomain entry.
📷 Vision Relay

Required for camera vision commands like tapclaw what do you see. A small background service on the same computer as TapClaw/OpenClaw receives camera frames and saves them to the workspace. That host can be Linux, a Mac, or a Windows PC.

Install instructions
Run on the same computer as TapClaw/OpenClaw:

Linux manual start:
python3 -m pip install Pillow
python3 tools/image_relay.py

macOS quick install:
pip3 install Pillow
bash tools/install-relay.sh

Windows manual start:
py -3 -m pip install Pillow
py -3 tools\\image_relay.py

The macOS script installs a background service that starts automatically on login. On Linux, use a systemd --user service, tmux, screen, or desktop autostart if you want the relay to auto-start. On Windows, use Task Scheduler or your Startup folder.

Manual start on any OS: python3 tools/image_relay.py
Uninstall macOS helper: bash tools/install-relay.sh --uninstall
Logs: /tmp/tapclaw-image-relay.log on macOS, your terminal / systemd journal / redirected log file on Linux, or your terminal / redirected log file on Windows
